# مواصفات واجهة بطاقة «ملخص الأدلة»

## الغرض

تعرض البطاقة خلاصة تعليمية سريعة للأدلة الفنية المتاحة قبل أن ينتقل المستخدم إلى البطاقات التفصيلية. لا تستخدم صياغة أمر تداول، ولا تخفي التعارض أو نقص البيانات خلف درجة رقمية واحدة. يجب أن يستطيع المستخدم خلال ثوانٍ فهم ثلاثة أمور: **هل الأدلة متفقة؟ هل البيانات كافية وحديثة؟ وما العوامل التي رفعت أو خفضت جودة القراءة؟**

تقع البطاقة في صفحة التحليل الفني بعد حالة مصدر البيانات مباشرة وقبل المخطط وبطاقات المؤشرات التفصيلية. هذا الموضع يضعها بعد معرفة المستخدم بالأصل والإطار ووقت آخر تحديث، وقبل أن يبدأ تفسير الرسم.

## التسلسل البصري

```text
┌──────────────────────────────────────────────────────────────┐
│ ملخص الأدلة                 [تحديث 12:41] [تغطية 82%]        │
│ توافق صاعد تعليمي                                         ↗   │
│ الأدلة الأساسية وICT متفقة؛ إطار 4h متحفظ.                  │
│                                                              │
│ جودة الاتفاق  ━━━━━━━━━━━●━━━━  74 / 100                    │
│                                                              │
│ [القراءة الأساسية +28] [Confluence ICT +25]                 │
│ [توافق الأطر +14]      [السياق المترابط +7]                 │
│                                                              │
│ عامل يحتاج الانتباه: إطار 4h لا يزال محايدًا.   [عرض الأسباب]│
└──────────────────────────────────────────────────────────────┘
```

يكون العنوان في أعلى اليمين في واجهة RTL، وتحاذى القيمة الرقمية والحالة معًا بصورة تمنع التباس أن الرقم توقع لعائد أو سعر. يظهر السهم أو الأيقونة كدعم بصري فقط، ولا يكون هو الوسيلة الوحيدة لتمييز الحالة.

## المستوى الأول: ملخص قابل للمسح السريع

| العنصر | المحتوى | القاعدة التصميمية |
|---|---|---|
| العنوان | «ملخص الأدلة» مع تلميح يشرح أنه تقييم للتوافق لا توصية | يبقى ثابتًا في كل الحالات |
| شارة الحالة | «توافق صاعد تعليمي»، «عوامل متعارضة»، «يحتاج تأكيدًا»، أو «بيانات غير كافية» | نص وأيقونة ولون، لا لون فقط |
| درجة جودة الاتفاق | من 0 إلى 100، مع عبارة «جودة اتفاق الأدلة» | لا تسمى «ثقة ربح» أو «احتمال نجاح» |
| درجة التغطية | نسبة المصادر المتاحة والحديثة من الركائز المتوقعة | منفصلة بصريًا عن جودة الاتفاق |
| الخلاصة | جملة واحدة تذكر أقوى اتفاق وأهم تحفّظ | بحد أقصى سطرين على الهاتف |
| حداثة النتيجة | وقت الحساب ووسم «متأخر» إذا لزم | لا تخلط بين وقت التحديث ووقت الشمعة |

تستخدم البطاقة لغة حذرة. مثال جيد: «توافق صاعد تعليمي؛ يؤيده التحليل الأساسي وConfluence ICT، بينما يبقى إطار 4h محايدًا». مثال غير مناسب: «فرصة شراء قوية» أو «السعر سيتجه صعودًا».

## فصل «التغطية» عن «جودة الاتفاق»

هما مقياسان مختلفان ويجب ألا يشتركا في مقياس واحد:

| المقياس | السؤال الذي يجيب عنه | مثال |
|---|---|---|
| **جودة الاتفاق** | إلى أي حد تتفق الأدلة المتاحة في اتجاه واحد؟ | 74/100 مع توافق أساسي وICT وأطر جزئية |
| **درجة التغطية** | كم من الركائز المتوقعة متاح وحديث؟ | 75% عند غياب السياق المترابط |

تُعرض التغطية على شكل شارة صغيرة في الرأس، وتفاصيلها عند التوسيع: `3 من 4 ركائز متاحة`، أو `السياق المترابط غير متاح`. أما جودة الاتفاق فتستخدم شريط تقدم واضحًا مع قيمة نصية، ويجب أن يضم `aria-label` وصياغة مثل: «جودة اتفاق الأدلة: 74 من 100».

## المستوى الثاني: تفصيل الركائز

عند الضغط على «عرض الأسباب» يظهر قسم قابل للطي. في سطح المكتب تظهر أربع خلايا، وعلى الهاتف تظهر قائمة عمودية. كل خلية تعرض اسم الركيزة وحالتها ومساهمتها وسببًا قصيرًا وحداثتها.

| الركيزة | حالة الخلية | مثال السبب | ما لا يجب عرضه |
|---|---|---|---|
| القراءة الأساسية | مؤيد/مخالف/محايد/غير متاح | «إشارة المزود صاعدة، ثقة 68%» | JSON الخام أو تفاصيل المزود غير المفهومة |
| Confluence ICT | مؤيد/محايد/محجوب بالبوابة | «بوابة ICT مكتملة: 5/7» | تكرار جميع المؤشرات في الملخص |
| توافق الأطر | مؤيد/مخالف/مختلط | «3 من 4 أطر تؤيد الاتجاه» | ادعاء أنه إشارة دخول مستقلة |
| السياق المترابط | مؤيد/سياقي/غير متاح | «الأصل المرجعي متوافق؛ مصدره حديث» | وزن كبير يجعل السياق يقلب اتجاه القرار |

تستعمل المساهمة صيغًا قابلة للفهم مثل `يدعم +25` أو `يقيّد −14` بدل الكشف المباشر عن معادلة داخلية. وتظهر عبارة «لم تدخل في الحساب» للعوامل غير المتاحة أو القديمة بدل وضعها بصفر غير مفسر.

## الحالات الحرجة

| حالة المحرك | أسلوب البطاقة | الإجراء الظاهر |
|---|---|---|
| `aligned_bullish` أو `aligned_bearish` | حد لوني هادئ أخضر أو أحمر، لا خلفية صارخة | «عرض الأسباب» |
| `needs_confirmation` | كهرماني مع شارة «يحتاج تأكيدًا» | «راجع بوابة ICT» يفتح تفصيل الركيزة |
| `conflicted` | محايد مائل للكهرماني/الوردي مع أيقونة تعارض | يعرض العاملين المتعارضين أولًا |
| `insufficient_data` | أزرق/رمادي هادئ مع علامة مصدر أو حداثة | «تحديث التحليل» مع وصف ما ينقص |
| `neutral` | رمادي واضح من دون دلالات إيجابية أو سلبية | «لا توجد أفضلية اتجاهية واضحة» |

لا يعطّل المحرك أزرار حفظ الإشارة أو فتح مسودة الصفقة الورقية تلقائيًا في الإصدار الأول؛ لكنه يعرض تحذيرًا في حالات التعارض أو نقص البيانات. تظل قواعد الخادم الحالية للصفقة الورقية مستقلة.

## تصميم الهاتف وإمكانية الوصول

على الهاتف يبدأ صف الرأس بعنوان البطاقة ثم شارة الحالة، وتنتقل شارتا «جودة الاتفاق» و«التغطية» إلى صفين مستقلين لتفادي ضغط النص. يظهر ملخص الركائز كسطرين افتراضيًا مع زر «عرض 4 عوامل»؛ لا تستخدم tooltip وحدها للمعلومات الضرورية لأن اللمس لا يضمن المرور بالفأرة.

تستخدم الألوان المميزة مع نص وصورة رمزية: صاعد، هابط، محايد، تحذير، وغير متاح. تبقى نسبة التباين مناسبة، ويكون قسم التفاصيل عنصر `Collapsible` أو `Accordion` قابلًا للوحة المفاتيح. تنطق قارئات الشاشة تغيّر الحالة عبر منطقة `aria-live="polite"` عند اكتمال بيانات جديدة، بينما تستخدم رسائل الأخطاء `role="alert"` فقط عند وجود مشكلة تؤثر في التفسير.

## مكونات React المقترحة

```text
UnifiedDecisionSummaryCard
├── DecisionStateBadge
├── EvidenceScoreMeter
├── CoverageBadge
├── DecisionSummaryText
├── DecisionWarnings
└── DecisionPillarBreakdown (قابل للطي)
    └── DecisionPillarItem × 4
```

تتلقى البطاقة عقد `UnifiedDecisionSummary` فقط، ولا تستدعي مصادر بيانات مستقلة من داخلها. بذلك يظل الحساب في الخادم قابلًا للاختبار، وتبقى الواجهة طبقة عرض حتمية وسهلة الاختبار.

## حالات اختبار الواجهة

| الاختبار | التحقق |
|---|---|
| توافق صاعد كامل | شارة الحالة، جودة الاتفاق، وتفصيل أربع ركائز موجبة |
| تعارض أساسي وICT | ظهور «عوامل متعارضة» قبل درجة رقمية، مع سببي التعارض |
| بوابة ICT حاجبة | ظهور «يحتاج تأكيدًا» وسبب البوابة دون شارة شراء/بيع |
| نقص السياق المترابط | تخفيض التغطية وعبارة «غير متاح» من دون أخطاء واجهة |
| مصدر بيانات محدود | رسالة بيانات غير كافية وزر تحديث واضح |
| هاتف RTL | ترتيب العنوان والعدادات والتوسيع صحيح، مع مناطق لمس لا تقل عن 44px |
| قارئ شاشة | تسمية المقاييس، الحالة، والتفاصيل القابلة للتوسيع متاحة |
