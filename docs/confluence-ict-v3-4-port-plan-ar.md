# خطة تحويل Confluence ICT V3.4 إلى طبقات AMIC

## الهدف

يستبدل محرك **Confluence ICT V3.4** طبقات AMIC البصرية الحالية الخاصة بالدعم/المقاومة والعرض/الطلب والاختراقات/الانعكاسات. سيُنفذ كـ **مؤشر مستقل مسجل** داخل محرك طبقات قابل للتوسع؛ لذلك لا يصبح مكوّن الشموع مربوطًا بسكربت Pine واحد ولا يلزم إعادة بنائه عند إضافة مؤشر ثانٍ مستقبلًا.

لا يُنفذ Pine Script داخل المتصفح أو الخادم. بل يُعاد تنفيذ منطقه بصورة حتمية في TypeScript على الشموع التاريخية والبث الحي، لتبقى النتيجة قابلة للاختبار والرسم داخل `lightweight-charts`.

## ما سيُستبدل

| طبقة AMIC الحالية | الحالة بعد التحويل | البديل من السكربت |
|---|---|---|
| دعم/مقاومة بنيوية | تُزال من واجهة الشارت | سيولة Equal High / Equal Low (`BSL` و`SSL`) ومناطق Order Blocks وFVG |
| عرض/طلب بنيوي | تُزال من واجهة الشارت | Bullish/Bearish Order Blocks ومناطق Bull/Bear FVG |
| اختراق/كسر/انعكاس | تُزال علاماتها الحالية | أحداث `BOS` و`CHoCH` وLiquidity Sweeps من السكربت |
| SMA 20/50 وEMA 12/26 | تُستبدل عند تفعيل المؤشر | EMA 20/50/200، أو القيم المتكيفة مع وضع Scalping |
| صندوق أحداث بنية السعر | يُستبدل بملخص المؤشر | حالة الاتجاه والسيولة وFVG ودرجة Confluence وسبب الإشارة |
| مستويات الصفقة الورقية | تبقى مستقلة | لا تتبع السكربت، لأنها مخرجات مسودة الصفقة التعليمية |

## مخرجات Confluence ICT V3.4

| المجموعة | المخرجات المرئية | منطق السكربت |
|---|---|---|
| الاتجاه والزخم | EMA سريع/متوسط/بطيء، RSI، MACD، Stochastic، ADX، OBV | اتجاه EMA الكامل وإشارات زخم/قوة محسوبة من الشموع |
| بنية السوق | BOS صاعد/هابط وCHoCH صاعد/هابط | كسر إغلاق آخر Swing High/Low قبل تحديثه بPivot جديد |
| السيولة | BSL وSSL وخطوط Equal High/Low وSweep | تقارب Pivotين ضمن tolerance، ثم كسر ذيل وعودة الإغلاق داخل المستوى |
| Order Blocks | مناطق Bullish وBearish OB | آخر شمعة معاكسة قبل BOS، مع حد أقصى وإزالة عند الإبطال |
| Fair Value Gap | مناطق Bull/Bear FVG ودرجة من 1 إلى 5 | فجوة ثلاث شموع بحد أدنى ticks/ATR، ودرجة اتجاه/بنية/سيولة/حجم فجوة |
| الإشارة | BUY أو SELL ودرجة Confluence/Scalping وأسبابها | نمط Normal أو Scalping، مع شروط Structure/Sweep/FVG/Momentum قابلة للتفعيل |
| الملخص | جدول حالة وسبب الإشارة | نفس حقول جدول Pine، لكن واجهة عربية متجاوبة بدل جدول TradingView الثابت |

## عقد طبقات المؤشر

المحرك الجديد يعيد عقدًا موحدًا حتى تستطيع مؤشرات لاحقة استخدام واجهة الرسم نفسها:

```ts
type ChartIndicatorResult = {
  id: string;
  lines: IndicatorLine[];
  zones: IndicatorZone[];
  levels: IndicatorLevel[];
  events: IndicatorEvent[];
  signals: IndicatorSignal[];
  summary: IndicatorSummary;
};
```

كل منطقة تحمل الاتجاه (`bullish` أو`bearish`) والنطاق السعري ووقت الإنشاء والحالة (`active` أو`mitigated` أو`expired` أو`invalidated`) ودرجة اختيارية. وكل حدث يحمل نوعه ووقت الشمعة والسعر وشرحًا عربيًا. لا يسمح للمؤشر بتعديل الشارت مباشرة؛ بل يعود بالبيانات إلى طبقة رسم موحدة، وهو ما يجعل إضافة سكربت جديد عملية تسجيل محرك آخر لا إعادة كتابة للمخطط.

## الإعدادات في AMIC

ستظهر بطاقة **Confluence ICT V3.4** بجوار المخطط، وبها: تفعيل المؤشر، الوضع Normal/Scalping، Preset، EMA، شرط/طول Swing، إعدادات OB، إعدادات FVG، إعدادات السيولة، وإظهار كل طبقة. الإعدادات تحفظ منفصلة باسم معرف المؤشر، كي لا تتداخل مع مؤشرات أخرى.

## حدود النقل المقصودة

المرحلة الأولى تنقل الحسابات والمناطق والخطوط والعلامات وملخص القرار. رسم مناطق Pine كصناديق ممتدة سيُحاكى بدايةً بحدي منطقة واضحين ومُلصق وصفي؛ إن احتجنا خلفية مستطيلة مطابقة، تضاف طبقة رسم مخصصة بعد تثبيت نتائج الحساب. كما تُفصل تنبيهات المستخدم إلى خطوة لاحقة كي تعمل على نفس محرك TypeScript، لا على شروط السوق القديمة.

## معايير القبول

يُقبل التحويل عندما تعطي بيانات شموع ثابتة نفس أحداث BOS/CHoCH والسيولة وFVG وإبطال المناطق المتوقعة، وتختفي الطبقات القديمة المحددة من واجهة التحليل، وتبقى مخارج الصفقة الورقية ومخطط الحجم سليمة، ويظل المؤشر قابلًا للإيقاف وإعادة التفعيل دون تراكب أو تسميات مزدحمة على الهاتف.
