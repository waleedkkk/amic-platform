# تدقيق أداء التصفح — دفعة محلية

## خط الأساس

أظهر بناء الواجهة قبل التحسين أن ملف JavaScript الرئيسي بلغ **3.16 MiB** (نحو **842 KiB** مضغوطًا). كان سبب ذلك أن `App.tsx` يستورد كل صفحات المنصة استيرادًا ثابتًا، فتدخل صفحات التحليل والدردشة والإدارة ومكتباتها في التحميل الأولي حتى عندما لا يفتح المستخدم تلك المسارات.

## التحسين الأول

تم تحويل صفحات المسارات إلى تحميل كسول باستخدام `React.lazy` و`Suspense`، مع حالة تحميل بسيطة قابلة للوصول أثناء فتح الصفحة لأول مرة.

بعد البناء المحلي، انخفض ملف الدخول الرئيسي إلى **0.72 MiB** (نحو **220 KiB** مضغوطًا). نُقلت الحمولات الثقيلة إلى ملفات مسارات عند الطلب، ومنها:

| المسار أو المكوّن | موضع التحميل بعد التحسين |
| --- | --- |
| مساعد AMIC وواجهة Streamdown | ملف صفحة المساعد عند فتح `/assistant` |
| الشارت و`lightweight-charts` | ملف التحليل عند فتح `/analysis` |
| رسوم الإدارة وRecharts | ملف الإدارة عند فتح `/admin` |
| الصفحات الثانوية | ملف مستقل لكل مسار عند زيارته |

يبقى تحذير بعض الملفات الكبيرة الخاصة بالصفحات النادرة، لكنه لم يعد يؤخر التحميل الأولي لبقية المنصة. ستستكمل الدفعة قياس الاستعلامات والتنقل واختبارات السلوك قبل أي نشر.

## تحسينات التصفح والاستعلامات

أضيف تحميل استباقي محدود لملف المسار عند تمرير المستخدم أو تركيزه على رابط في الشريط الجانبي. بذلك يبدأ تنزيل الصفحة المحتملة فقط عند وجود نية تصفح، مع بقاء التحميل الأولي خفيفًا.

كما حُفظ الشريط الجانبي في موضعه أثناء تحميل الصفحة المؤجلة، فتظهر حالة «جارٍ فتح الصفحة…» داخل مساحة المحتوى بدل استبدال الواجهة كلها.

وضُبطت ذاكرة TanStack Query المشتركة بحيث تبقى النتائج صالحة لمدة 30 ثانية، ولا تعيد الجلب تلقائيًا عند كل عودة إلى النافذة، مع محاولة إعادة واحدة فقط. الاستعلامات التي تحتاج تحديثًا حيًا تحتفظ بإعداداتها الصريحة في مكوّناتها.

أخيرًا، أصبحت بطاقات التحليل الفني الثانوية — توافق الأطر، والسياق الخارجي، وخريطة نشاط الجلسات — لا تُركّب ولا تطلق طلبات بياناتها إلا عند الاقتراب منها أو اختيار «تحميل الآن». لا يؤخر ذلك الشارت والملخص الأساسيين.

## حدود القياس

تم قياس حجم البناء محليًا والتحقق من الاختبارات. لم يُجرَ قياس زمني مصادق عليه لطلبات صفحات المستخدم الداخلية، لأن جلسة مستخدم حقيقية لم تُستخدم في هذه الدفعة. ينبغي قياسها لاحقًا من المتصفح بحساب فعلي قبل ادعاء أرقام زمنية محددة للاستعلامات الخلفية.

## تنفيذ الدفعة الأولى من كاش السوق

كان مسار الشموع يحتوي أصلًا على طبقة ذاكرة L1 ولقطات مشتركة في `marketSnapshots` ومنعًا للطلبات المتزامنة. تم توسيعه محليًا بدل استبداله:

| التحسين | السلوك الحالي |
| --- | --- |
| وصف طبقة الكاش | يعيد مسار الشموع `cacheStatus` بقيم `memory` أو `snapshot` أو `fresh`، مع وقت المصدر ووقت الحفظ وانتهاء الصلاحية |
| منع التكرار | تبقى الطلبات المتزامنة للمفتاح نفسه مشتركة في Promise واحدة، ويُحذف المفتاح بعد النجاح أو الفشل |
| واجهة الشارت | تعرض الشارت «جُلبت الآن» أو «ذاكرة الخادم» أو «لقطة مخزنة» إلى جانب اسم مصدر الشموع ووقت الجلب |
| الدقة | لا يعرض المسار قراءة قديمة منتهية الصلاحية كأنها حالية؛ `isStale` يظل `false` في هذه الدفعة |

تؤجل القراءة القديمة مع التحديث الخلفي وقياس زمن المسارات وإدماج التحليل والماسح إلى دفعات لاحقة بعد مراجعة أثر كاش الشموع في بيئة مصادق عليها.

## قياس أداء الكاش محليًا

أضيف تجميع داخل عملية الخادم لمسار الشموع فقط. يسجل التجميع عدد الطلبات الناجحة والفاشلة، وحالات `memory` و`snapshot` و`fresh`، ومتوسط زمن الاستجابة وP95 لعينة محدودة. لا يسجل الرموز أو البورصات أو `userId` أو محتوى الطلبات أو المحادثات أو المفاتيح. يعاد ضبط القياس عند إعادة تشغيل الخدمة ولا يعد بديلًا عن مراقبة طويلة الأجل.

يظهر الملخص للمدير فقط في تبويب **صيانة السوق والكاش**. يعرض عدد الطلبات، إصابات الكاش، المتوسط وP95، ويصرح بوضوح بأنه «قياس محلي» للمثيل الحالي. لم تُضف جداول جديدة أو ترحيلات قاعدة بيانات لهذه الدفعة.
