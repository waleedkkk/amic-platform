# توثيق التنفيذ المحلي لخطة AMIC

## النطاق

تم تنفيذ مراحل محرك القرار الموحّد، بطاقة ملخص الأدلة، التحميل التدريجي لـConfluence، اختبارات الهاتف، وقناة WebSocket لتنبيهات إغلاق الصفقات الورقية. التغييرات محلية فقط؛ لم يُحفظ checkpoint ولم تُدفع تغييرات إلى GitHub ولم تُنشر إلى IBM.

## محرك القرار والبطاقة

يُجمع التحليل الأساسي مع Confluence ICT، وتوافق الأطر والسياق المترابط عند توفرهما، في `shared/unifiedDecision.ts`. يعيد المحرك حالة وصفية ودرجة اتفاق وتغطية ومساهمات وأسبابًا، ولا ينفذ أوامر تداول.

تعرض `UnifiedDecisionSummaryCard` حالة القرار، جودة الاتفاق، تغطية الركائز، المساهمات، وأسباب التعارض في تخطيط عربي متجاوب. أضيفت اختبارات للتوافق والتعارض وحجب بوابة ICT ونقص البيانات وتوسيع الأسباب.

## التحميل والأداء

يستخدم `useNearViewport` و`LazyConfluenceBreakdownPanel` مراقبة `IntersectionObserver` مع هامش اقتراب، تحميل يدوي احتياطي، و`enabled` في استعلام tRPC. لا يبدأ استعلام Confluence قبل الاقتراب أو طلب المستخدم، مع كاش زمني ومحاولة إعادة واحدة.

## WebSocket

أُضيف `paperTradeSocket.ts` على نفس خادم HTTP في Express، مع:

- مصادقة الترقية باستخدام session cookie ومحلل `resolveSessionUser`.
- سجل اتصالات منفصل لكل `userId`.
- فحص Origin في الإنتاج والحد من حجم الرسائل.
- heartbeat بـping/pong وتنظيف الاتصالات غير النشطة.
- قناة push-only؛ إغلاق الصفقة لا يتم عبر WebSocket.
- ناقل أحداث مستقل في `paperTradeEvents.ts` لتجنب دورة الاستيراد مع `db.ts`.
- حدث تحذير عند طلب تأكيد انحراف السعر، وحدث تحديث بعد الإغلاق الفعلي.

تستقبل `usePaperTradeAlerts` الأحداث وتزيل التكرارات حسب `eventId`، وتعيد الاتصال بتأخير متزايد، وتحتفظ بعدد محدود من التنبيهات. يعرض `PaperTradeAlertCenter` مؤشر الاتصال، مركزًا محليًا للتنبيهات، وتنبيهًا قابلًا للمراجعة، مع الحفاظ على حوار التأكيد ذي المرحلتين.

## CI واختبارات الهاتف

أضيف `@playwright/test` وملف `playwright.config.ts` بمشروع Chromium يحاكي Pixel 5 بعرض 375×812 وبيئة عربية. يتحقق اختبار الهاتف من عدم تجاوز `document.documentElement.scrollWidth` لعرض النافذة. اختبار بطاقة التحليل يُفعّل عند تزويد جلسة مصادق عليها، ويُتخطى دونها بدل استخدام حساب حقيقي.

أضيف اختبار الهاتف إلى وظيفة `verify` في `deploy-ibm.yml` بعد تثبيت Chromium، وقبل فحص TypeScript وبناء الإنتاج. وبذلك يمنع فشل الاختبار وظيفة النشر لاحقًا.

## التحقق المحلي

نجحت الاختبارات المستهدفة لـWebSocket وHook، ونجحت اختبارات Playwright للهاتف بحالة مرور وحالة متخطاة بسبب حماية صفحة التحليل، ثم نجحت مجموعة Vitest الكاملة وفحص TypeScript وبناء الإنتاج وفحص `git diff --check` قبل آخر تعديل بسيط لمنع Toast نجاح مكرر. يجب إعادة تشغيل التحقق الكامل بعد آخر تعديل قبل إنشاء checkpoint.

## الملاحظة المتبقية

سجل المتصفح يحتوي على أثر تاريخي لخطأ `chartLayerColorKeys`، بينما التصدير موجود حاليًا وفحص TypeScript والبناء ناجحان. يجب اعتماد جلسة مصادق عليها وفحص بصري للبطاقة وصفحة التداول قبل أي نشر، ثم مراقبة GitHub Actions وHTTP 200 ومسار الإغلاق في الإنتاج بعد موافقة صريحة.
